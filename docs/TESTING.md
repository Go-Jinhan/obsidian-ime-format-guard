# 테스트와 재현 기록

## 확인된 범위

2026-11-05, macOS의 Obsidian 1.14.5 / 설치 프로그램 1.14.4에서 확인했습니다.

| 검사 | 결과 | 한계 |
| --- | --- | --- |
| 사용자의 실제 한글 입력 → Cmd+B / Cmd+I | 개인용 0.3.0 적용 후 중복 해결 확인 | 한 사용자의 환경이며 전체 맥 환경을 대표하지 않음 |
| 별도 노트에서 조합 → 서식 → 확정 자동 입력 | 미적용 시 `**안녕**녕`, 적용 후 `**안녕**` | 앱의 Chromium 입력 인터페이스를 통한 재현이며 물리 키보드 입력과 구분 |
| 공개용 0.3.1의 실제 편집기 자동 재현 | 굵게 적용 후 `**안녕**`, 중복 없음 | 공개용 파일·포커스 보호 로직을 포함한 실행 확인 |
| 개인용 0.3.0의 추가 자동 재현 | `*안녕하세요*`, `**테스트**`, `*녕녕*`, 영문 서식 통과 | 다른 운영체제는 미검증 |
| 공개용 0.3.1 단위 테스트 | 14개 통과 | 이벤트 순서와 정리 동작을 검사하는 모의 환경 |

README의 전후 화면은 공개용 버전을 테스트한 별도 노트의 편집 영역만 캡처했습니다. 볼트 이름, 파일 목록, 개인 노트는 포함하지 않습니다. 테스트 후 노트와 임시 설치본을 정리하고 기존 앱 상태를 복원했습니다.

## 수동 재현

1. 테스트용 볼트 또는 노트를 열고 플러그인을 비활성화합니다.
2. 한글 입력기를 선택하고 `안녕`을 입력합니다.
3. 공백·방향키로 마지막 음절을 확정하지 않은 상태에서 Cmd+B를 누릅니다.
4. 마지막 글자가 추가되는지 확인합니다. 재현되지 않는 환경도 있을 수 있습니다.
5. 플러그인을 활성화하고 같은 순서를 반복합니다.
6. Cmd+I, `안녕하세요`, `녕녕`, 영문 입력, 선택 영역에 대해서도 확인합니다.
7. 비활성화 후 기본 서식 동작으로 복원되는지 확인합니다.

검증할 추가 상황: 서식 대기 중 다른 파일 열기, 다른 탭으로 이동, 연속 단축키, 앱 재시작, 다른 플러그인과의 조합, 1.5초 동안 조합이 끝나지 않는 경우입니다.

## 자동 재현에서 사용한 순서

다음은 개발자 도구를 이용한 테스트 순서의 설명입니다. 실제 개인 노트에 실행하지 않습니다.

```text
테스트 편집기에 '안' 입력, 커서를 끝에 놓기
Input.imeSetComposition(text='녕', selectionStart=1, selectionEnd=1)
Cmd+B 입력 전달
Input.insertText(text='녕')
편집기 본문과 composition 상태 확인
```

처음에는 명령 실행 전후를 모의 코드로만 검사했기 때문에 실제 macOS 입력 중복을 놓쳤습니다. 최종 구현에서는 편집기에서 중복을 먼저 재현하고 같은 순서로 수정본을 비교했습니다. 테스트 통과를 모든 입력기 호환성으로 해석하지 않습니다.

## 단위 테스트

```sh
npm test
```

- 조합 중이 아닌 입력의 즉시 실행
- 굵게·기울임 각각의 조합 종료 후 실행
- 조합 시작 단계 처리
- 대기 중 반복 호출 제한
- 타임아웃 및 이벤트·타이머 정리
- 편집기·파일 변경, 포커스 이동, DOM 제거 시 취소
- 비활성화 시 원래 콜백 복원
- 다른 플러그인의 후속 래퍼 보존
- 명령이 없는 경우의 로드
- 반복 조합 종료 이벤트의 중복 실행 방지
